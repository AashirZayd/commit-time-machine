:: SYSTEM RATIONALE — WHY THIS EXISTS
[ COMPARATIVE ANALYSIS ]
THE RAW LOG APPROACH
Raw Commits Without Synthesis

Standard git log prints individual SHAs, authors, and commit messages line-by-line. Answering higher-level questions about evolution, churn, and directory clusters requires manual correlation across hundreds of commits.

  • Raw lists without contextual synthesis
  • Commits from merged branches frequently hidden with shallow flags
  • Checking out older revisions mutates working tree and HEAD
  • Comparing historical points requires manual diff plumbing
THE TIME MACHINE APPROACH
Structured Evolutionary Timeline

commit-time-machine operates as an interpretation and exploration layer over Git plumbing. It parses reachable history, detects churn bursts, classifies change magnitude, and enables instant point-in-time exploration.

  • Deterministic interpretation of commit volume and focus areas
  • Full reachable commit DAG traversed by default
  • Read-only historical snapshots without git checkout
  • Instant range comparisons and file rename tracking
:: EXECUTION PIPELINE — HOW IT WORKS
[ 4-STAGE PIPELINE ]
[ 01 ] EXPLORE
Plumbing Extraction
Executes read-only Git plumbing vectors (null-delimited log/show) without shell interpolation to collect raw commit objects and parent pointers.
[ 02 ] ANALYZE
Churn & Clusters
Computes churn magnitude (Small / Medium / Large), clusters modifications by top-level directory, and detects contributor burst patterns.
[ 03 ] INTERPRET
Deterministic Synthesis
Synthesizes observable facts into a coherent summary of recent repository activity without AI hallucination or speculative analysis.
[ 04 ] RENDER
Timeline / TUI / JSON
Dispatches presentation to high-hierarchy terminal format, keyboard-driven interactive TUI, or pure validated JSON for automation.

KEYBOARD CONTROLS & SPECIFICATION
Full TTY Exploration Interface

Run commit-time-machine --interactive to enter keyboard-driven history navigation. Drill down into commit details and view bounded diff previews directly inside the terminal.

Key Action
↑ / ↓ or k / j Navigate commits backwards / forwards
Enter Inspect selected commit details & touched files
d Bounded diff preview (from detail view, max 80 lines)
Esc / Backspace Return to previous view
q Exit cleanly and restore terminal buffer
TTY Requirement: Interactive mode requires a real terminal. When invoked in non-TTY environments (pipes, redirects, CI runners), it terminates cleanly with descriptive diagnostic advice.
:: SYSTEM CAPABILITIES — TECHNICAL FEATURES
[ 6 CORE MODULES ]
[ 01 ] TRAVERSAL
Full Reachable DAG

By default, traverses the complete reachable commit graph. Commits from merged feature branches are never hidden unless --first-parent is explicitly supplied.

[ 02 ] SNAPSHOTS
Time Travel (--at)

Use --at <commit> to inspect what your repository looked like at any historical commit: root directory structure, file counts, and parent churn.

[ 03 ] COMPARISON
Historical Range

Compare differences between any two historical points with --compare <c1> <c2> without checking out either commit.

[ 04 ] FILE TRACING
Rename & Delete Tracking

Trace a file's evolution through moves, renames, and even deletions with --file <path>, even if the file is absent in the current working tree.

[ 05 ] FILTERING
Search & Author Filter

Locate specific changes with case-insensitive --search "<query>" or isolate individual contributions with --author "<name>".

[ 06 ] MAINLINE
First-Parent Filter

Follow only the first parent upon merges with --first-parent to focus cleanly on release integration and mainline evolution.

:: COMMAND REFERENCE & CLI EXAMPLES
[ VERIFIED ARGUMENTS ]
COMMAND / OPTION TECHNICAL DESCRIPTION
commit-time-machine Display recent repository timeline across full reachable commit DAG
commit-time-machine --limit 20 Browse the last 20 commits with churn classifications and directory focus
commit-time-machine --interactive Launch keyboard-driven interactive terminal timeline explorer
commit-time-machine --at HEAD~5 Inspect historical repository snapshot structure without checkout
commit-time-machine --compare v0.1.0 main Compare files added, modified, and deleted between two historical points
commit-time-machine --file README.md Trace historical evolution of a specific file across renames
commit-time-machine --search "authentication" Search commit messages and subjects case-insensitively
commit-time-machine --author "Aashir" Filter commits by author name or email pattern with activity counts
commit-time-machine --first-parent Show mainline / integration history only, excluding merged branch commits
commit-time-machine --json Emit pure machine-readable JSON without banners or ANSI escape codes
:: MACHINE-READABLE OUTPUT — STRUCTURED JSON
[ FLAG: --json ]
BUILT FOR AUTOMATION
Pure JSON On Stdout

When --json is provided, commit-time-machine suppresses all decorative banners, ASCII art, and ANSI escape sequences. Stdout contains strictly valid, machine-readable JSON.

Every payload includes a top-level "mode" discriminator (timeline, snapshot, compare, search, author, commit, file) for reliable parsing inside scripts, CI pipelines, and custom dashboards.

:: SYSTEM SAFETY — READ-ONLY INTEGRITY
[ TRUST GUARANTEES ]
OBSERVER-ONLY OPERATION
Your Repository Stays Untouched

A Git developer utility should never risk corrupting your active working environment. commit-time-machine functions exclusively as an observer. It never alters your files, index, or HEAD pointer.

  • No checkout, switch, or branch alterations
  • No reset, restore, or clean commands
  • No stash creation or working tree modifications
  • No network calls, telemetry, or remote pushes
