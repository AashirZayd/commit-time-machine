The Problem

Why commit-time-machine?

git log shows what commits exist. But when joining a new codebase, reviewing a large refactor, or debugging a regression, developers need to understand how the project arrived at its current state.

The Raw Log Approach
Raw commits without synthesis

Git logs print SHA hashes, author names, and commit messages line by line. Understanding the arc of change requires manually cross-referencing parents, churn volume, directory clusters, and branches.

  • Raw lists without high-level context
  • Merged branch commits often hidden with shallow flags
  • Checking out past states modifies working trees and HEAD
  • Comparing arbitrary points requires manual diff plumbing
The Time Machine Approach
Structured evolutionary timeline

commit-time-machine interprets Git history deterministically. It synthesizes directory focus, classifies churn magnitude, inspects past file trees, and provides an interactive terminal UI.

  • Deterministic interpretation of commit volume and focus areas
  • Full reachable commit DAG traversed by default
  • Non-destructive historical snapshots without git checkout
  • Instant range comparisons and rename tracking
Capabilities

Engineered for Git Exploration

Every capability is built directly on Git plumbing with strict read-only execution.

Full Reachable History

By default, traverses the complete commit DAG. Commits from merged feature branches are never hidden unless you explicitly pass --first-parent.

Time Travel Snapshots

Use --at <commit> to inspect what your repository looked like at any historical commit: root structure, file counts, and changes relative to parent.

Historical Comparisons

Compare any two points in history with --compare <c1> <c2>. See files added, modified, or removed across releases without checking out either commit.

File Rename Tracking

Trace file evolution across renames, refactors, and even deletions with --file <path>. Inspect its history even if the file is no longer in the working tree.

Commit Search & Author Filter

Quickly locate relevant changes using case-insensitive --search "<query>" or isolate individual contributions with --author "<name>".

Strictly Read-Only & Offline

Zero mutations to Git state. Never touches working trees, never checks out commits, never creates stashes, and never issues external network requests.

Keybindings & Behavior

↑ / ↓ or k / j Navigate commits backwards / forwards
Enter Inspect selected commit detail & touched files
d Bounded diff preview (from detail view, max 80 lines)
Esc / Backspace Return to timeline view from detail or diff
q Exit cleanly and restore terminal screen
TTY Required: Interactive mode requires a real terminal. When executed inside non-TTY environments (CI runners, pipes, redirects), it exits gracefully with clear diagnostic guidance.
Command Reference

Practical Command Examples

Every command is deterministic, composable, and executes against local repository state.

Browse recent commits
commit-time-machine --limit 20

Traverse the last 20 reachable commits with churn classifications and directory clusters.

Launch interactive mode
commit-time-machine --interactive

Keyboard-driven terminal navigation with commit detail and bounded diff previews.

Inspect a historical snapshot
commit-time-machine --at HEAD~5

Inspect repository structure, file count, and top-level folders at an exact commit.

Compare two historical points
commit-time-machine --compare v0.1.0 main

Compare file additions, modifications, and deletions between two revisions.

Follow file across renames
commit-time-machine --file README.md

Trace historical modifications to a file even after moves, renames, or deletions.

Search commit messages
commit-time-machine --search "authentication"

Case-insensitive search across commit subjects and messages.

Filter by author
commit-time-machine --author "Aashir"

Show commit counts, recent timeline, and activity for a specific contributor.

Mainline / first-parent only
commit-time-machine --first-parent

Follow only the first parent of merge commits to isolate release integration history.

Design Principles

Safe, Read-Only, and Deterministic

A development tool should never risk damaging your working state.

100% Read-Only

Zero mutation. Never executes checkout, switch, reset, restore, merge, or stash. Working tree files are never altered.

100% Offline

Zero network calls, zero telemetry, zero analytics tracking. Operates entirely against the local Git repository on your machine.

Pure Architecture

Strictly decoupled pipeline: Git Plumbing Collection → Analysis Engine → Deterministic Interpreter → Terminal / JSON Renderer.
